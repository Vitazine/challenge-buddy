# UI smoke Challenge Buddy — v2

Агент выполняет действия через расширение Chrome (согласованная замена
Playwright MCP). Создание файла браузерного теста не заменяет фактический
проход по UI. Клики и ввод — поддерживаемыми browser API; evaluate допустим
только для чтения DOM, не для fetch или подмены состояния.

## Стенд и доказательства

- Сначала `./scripts/pnpm.sh check`, затем
  `./scripts/pnpm.sh exec node --import tsx scripts/testing/smoke-server.mjs`.
- Адрес `http://127.0.0.1:3001`, чистая временная SQLite, локальный тестовый
  пользователь, серверные часы `2026-10-24T12:00:00Z`. Рабочая БД и .env
  не используются. Не открывать этот сервер через туннель.
- В фиксированный момент локальное сегодня во всех поясах устройства —
  24 или 25 октября. Значения today/max читать из подсказки и min/max формы;
  для Asia/Manila ожидаются `2026-10-24` / `2026-10-31`, +8 — `2026-11-01`.
- Каждый нумерованный шаг: действие → ожидание видимого результата → DOM
  и полный скриншот `test-results/current/screenshots/S<n>-<step>.jpg` → PASS/FAIL,
  expected/actual. Снимки и временные логи не добавляются в Git.
  При несовпадении сохранить фактическое состояние и причину; после исправления
  начинать новую попытку, не заменять старые доказательства.
- `check` начинает новый прогон и удаляет прошлые снимки. Для повтора внутри
  текущего прогона использовать `check:code`/`test:unit` и новый префикс файлов,
  без `test:prepare`. Перезапуск smoke-сервера сохраняет предыдущие попытки.
- Для допустимой даты не ограничиваться `fill` у `input[type=date]`: в текущем
  расширении он может поменять видимое DOM-значение без обновления React-state.
  Ввести предшествующий день и нажать ArrowUp, затем Tab; после изменения
  названия (повторного render) убедиться, что дата сохранилась. Для +7 в Manila:
  fill `2026-10-30` → ArrowUp → Tab → DOM `2026-10-31`. Если получился другой
  сегмент даты, выбрать день нативной клавиатурой/календарём и снова проверить.
  Недопустимую +8 можно задать прямым fill для проверки нативной validity;
  это отдельно от проверки React-state допустимой даты.
- Сценарии ниже проходят цепочкой на записи «День 3 — основной smoke».
  Для отдельного запуска S2–S4 предварительно создать отдельную запись на
  сегодня, сроком 3 дня; для S3/S4 поставить сегодняшнюю отметку через UI.
- Перезагрузка означает reload страницы с последующим открытием деталей из
  списка: внутренний экран деталей не хранится в URL.
- В конце сохранить console warnings/errors, статусы HTTP из лога стенда,
  общий отчёт и остановить процесс Ctrl+C. Временная БД удаляется самим стендом.

## S1. Создание и сохранение

Предусловие: свежий стенд, обычный список пуст.

1. Открыть приложение. Видны пустой список и создание, локальная сессия
   разрешает работу без Telegram.
2. Нажать создание. Форма загрузила диапазон дат, поля и сохранение доступны.
3. Ввести «День 3 — основной smoke», срок 3 дня, старт сегодня. Поля содержат
   введённые значения.
4. Сохранить. Открылись детали с названием, 0%, 0 из 3 и возможностью отметки.
5. Вернуться в список и перезагрузить страницу. В списке ровно одна такая запись.

## S2. Отметка и сохранение

Предусловие: запись S1, отметок нет.

1. Открыть запись. Видны 0%, 0 из 3 и кнопка отметки.
2. Отметить сегодня. Видны 33%, 1 из 3, один выполненный день и кнопка отмены.
3. Перезагрузить страницу. Запись в списке показывает 33%.
4. Открыть запись снова. История по-прежнему содержит ровно одну отметку.

Повторный клик по кнопке здесь означает отмену; идемпотентность повторного
PUT проверяется интеграционным tests/api.test.ts, не этим сценарием.

## S3. Отмена

Предусловие: запись S2 с одной отметкой.

1. Нажать отмену сегодняшней отметки. Видны 0%, 0 из 3 и кнопка отметки.
2. Вернуться в список. Карточка показывает 0%.
3. Открыть запись снова. Отметки нет, результат отмены сохранён.

## S4. Архив и история

Предусловие: запись S3, отметок нет.

1. Отметить сегодня. В деталях 33%, 1 из 3.
2. Архивировать, затем вернуться в обычный список. Запись исчезла из него.
3. Открыть архив. В нём ровно одна запись с прежним названием и 33%.
4. Открыть архивные детали. История сохранена, кнопок отметки/отмены нет.
5. Вернуться назад. Открылся архив; переход в «Мои челленджи» показывает
   пустой обычный список.

## S5. Верхняя граница даты

Предусловие: обычный список открыт, допустимые даты определяются сервером.

1. Открыть создание. Видна серверная верхняя граница today +7.
2. Ввести «День 3 — граница даты», срок 3 дня, startDate = today +8.
   Поле содержит дату за пределами max.
3. Нажать сохранение. Форма остаётся открыта, браузерная валидация/сообщение
   запрещает сохранение. Прочитать validity.rangeOverflow; POST отсутствует
   в логе на этом шаге.
4. Вернуться в обычный список. Записи «День 3 — граница даты» нет.
5. Снова открыть создание и заполнить те же название/срок, startDate = today +7.
   Использовать клавиатурное изменение даты по инструкции выше; поле допустимо
   и сохраняет выбранную дату после повторного render.
6. Сохранить. В деталях выбранная дата +7 сохранена, статус будущего челленджа,
   0%, кнопки отметки нет. Вернуться в список: появилась ровно одна запись.

Прямой POST с +8 и отсутствие записи после серверного отказа покрываются
tests/start-date.test.ts. UI-smoke не выдаётся за проверку серверной защиты.
