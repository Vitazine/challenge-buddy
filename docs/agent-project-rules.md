# Challenge Buddy — сжатые правила проекта

## Стек и команды

Telegram Mini App личных челленджей. Node.js 24, pnpm 11.25.0, TypeScript strict/ES modules; React 19, Vite 7, CSS; Fastify 5, Zod 4, `node:sqlite`. Не добавляй зависимости, инструменты тестирования и возможности других дней без необходимости согласованной задачи. Восстановление архива, напоминания и группы не входят в текущую область.

- Разработка: `./scripts/pnpm.sh dev`; полный контроль: `./scripts/pnpm.sh check`.
- Части контроля: `typecheck`, `lint`, `test`, `build` через ту же обёртку.
- Тесты: `node:test`, `node:assert/strict`, существующие helpers. Изолированные БД, управляемые часы, закрытие ресурсов через `t.after`.
- При tsx IPC `EPERM` сохрани исходную ошибку; используй штатное разрешение или эквивалент `./scripts/pnpm.sh exec node --import tsx --test tests/*.test.ts`. Не меняй продукт или проверки ради sandbox.

## Границы слоёв

React → `src/api.ts` → `server/app.ts` → `ChallengeService` → `ChallengeRepository` → SQLite.

- `src/components/`: доступное представление и props; `src/hooks/useChallengeApp.ts`: экраны, загрузка, блокировка повторных мутаций, Telegram BackButton.
- `src/api.ts`: HTTP, заголовки авторизации, таймаут и единое представление ошибок.
- `server/app.ts`: строгие Zod-схемы на входе, подтверждённый владелец, HTTP-статусы. Бизнес-правила в `server/challenges.ts`, часы передаются зависимостью.
- SQL и схема только в `server/repository.ts`; параметризованные запросы, выборка по id и владельцу. Миграции сохраняют записи, отметки и индексы; INSERT перечисляет столбцы.
- `shared/contracts.ts`: типы из схем, общие контракты; `shared/dates.ts`: календарные функции. Сохраняй существующие имена, enum и формат ошибок вместо навязывания общих шаблонов.
- Сервер определяет текущую дату, сроки, числовой прогресс и разрешения. UI отображает серверные значения; клиентская проверка не является защитой.
- При изменении поведения актуализируй README и `docs/architecture.md`.

## Код и интерфейс

PascalCase для компонентов и классов, camelCase для значений, `use…` для хуков. Имена файлов по соседним. Двойные кавычки, точки с запятой, два пробела, Prettier; именованные экспорты и `import type`. Порядок импортов: внешние → shared → внутренние. Сужай `unknown`, не добавляй `any`, `@ts-ignore`, небезопасные приведения или подавления проверок.

Русские пользовательские тексты. Сохраняй зелёные/лаймовые CSS-переменные, классы и адаптивность. Семантические кнопки, видимые подписи, состояния загрузки, ошибки и пустого списка; действия блокируются во время сохранения. Компонент: импорты → props → именованная функция → представление; fetch и правила остаются в соответствующих слоях.

Перед изменением загрузки прочитай `eslint.config.js`. Не вызывай синхронную цепочку setState из тела effect: обновления загрузки выполняются в асинхронных callback после await/Promise, pending/loading действий — в обработчиках. После изменения хука запусти lint без таймеров и отключений правила.

## Данные, безопасность и инварианты

- Владелец только из существующей серверной авторизации. Не доверяй `initDataUnsafe` и ownerId из тела. Чужой и отсутствующий объект одинаково недоступны.
- Секреты, реальные initData и частные эксплуатационные данные не попадают в код, логи или артефакты. Не читай рабочую БД для тестов; не оставляй отладочный console.log.
- Версию SQLite читай до DDL и изменяющих файл PRAGMA. Поддерживаемая версия задана явно: 0 → новая текущая схема, известные старые → последовательная транзакционная миграция, текущая → без повторного ALTER. Будущую отклоняй с закрытием соединения без изменения схемы, user_version и данных. При затрагивании миграций проверь отдельные файловые БД: новую, v1 с историей, повторное открытие v2, будущую версию.
- Архив: `archivedAt: string | null` независимо от `upcoming | active | finished`; повтор сохраняет первоначальную дату. История и прогресс сохраняются, PUT и DELETE отметок запрещены сервером. Одинаковый фильтр items/total и изоляция владельца обязательны.
- Сохраняй защиту от устаревших ответов списка и деталей, включая фоновый запрос до мутации. Смена вида сбрасывает страницу; исчезновение последней записи возвращает допустимую страницу. Проверяй возврат из архивных деталей в архив и переход в обычный список, когда затронута навигация.
- Проверяй наблюдаемое поведение, а не текст реализации. Скриншот не доказывает отсутствие гонки; явно укажи, выполнен ли управляемый сценарий или был только статический анализ.
