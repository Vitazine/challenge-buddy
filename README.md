# Challenge Buddy

Telegram Mini App для личных челленджей: небольшое действие каждый день, отметки и видимый прогресс.

## Что готово

- Список челленджей с пагинацией и пустым состоянием.
- Создание: название, дата старта, длительность 1–30 дней.
- Детали: календарь, процент выполнения, отметка за сегодня и ее отмена.
- Хранение в SQLite; данные сохраняются при перезапуске.
- Проверка Telegram initData на сервере и изоляция пользователей.
- Отдельный локальный профиль для разработки без бота.

## Стек

| Часть | Решение | Зачем |
|---|---|---|
| Интерфейс | React 19 + TypeScript | Компоненты и строгие типы |
| Разработка и сборка | Vite 7 | Быстрый локальный запуск и компактная сборка |
| Сервер | Fastify 5 + TypeScript | Небольшой типизированный REST API |
| Данные | SQLite через встроенный `node:sqlite` | Один файл, без отдельного сервера БД |
| Валидация | Zod 4 | Одинаковые правила формы и API |
| Проверки | Node test runner + tsx, ESLint, TypeScript | Бизнес-логика, API и авторизация |
| Среда | Node.js 24 LTS, pnpm 11.25.0 | Зафиксированная воспроизводимая среда |

Точные версии зависимостей записаны в `pnpm-lock.yaml`. Встроенный SQLite в Node 24 имеет экспериментальный статус; для этого небольшого учебного проекта это осознанный компромисс. Слой repository изолирует драйвер от остального кода.

## Запуск

Обычная среда с Node.js 24 и pnpm 11.25.0:

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm dev
```

На текущем Mac команды `node` и `pnpm` не находятся в стандартном PATH. Добавлена обертка, использующая установленную среду desktop-приложения:

```sh
./scripts/pnpm.sh dev
```

Откройте http://127.0.0.1:5173. Остановка — Ctrl+C в терминале, где запущен сервер.

`dev` запускает UI на 5173 и API на 3001 с локальным профилем. Для изменения серверного кода перезапустите `dev`; интерфейс обновляется автоматически. Данные находятся в `data/challenge-buddy.sqlite`. В локальном профиле все проверки используют одного тестового пользователя. Созданный при проверке челлендж «Учиться вайб-кодингу» — тестовый пример.

## Проверки

```sh
./scripts/pnpm.sh check
./scripts/pnpm.sh audit
```

`check` запускает типы, линтер, тесты и сборку. Установка выполняется без install-скриптов зависимостей (`.npmrc`); для текущей платформы запуск и сборка проверены с этой политикой. Автоматический `audit fix --force` не используется.

## Структура

```text
src/                 React: экраны, компоненты, клиент API, Telegram-адаптер
  components/        Форма, карточка, детали, индикатор прогресса
server/
  app.ts             HTTP-маршруты, проверка входных данных и доступ
  auth.ts            Проверка подписи и свежести Telegram initData
  challenges.ts      Правила челленджей и вычисление прогресса
  repository.ts      Параметризованные SQL-запросы и схема SQLite
  index.ts           Конфигурация и запуск сервера
shared/              Общие типы, схемы валидации, календарные функции
tests/               Автотесты API, авторизации и бизнес-логики
scripts/             Запуск локальной среды
docs/                Учебный план, архитектура и результаты проверки
Tasks/               Исходные задания курса
data/                Локальная база; исключена из Git
dist/                Сборка интерфейса; исключена из Git
```

## Бизнес-правила

- Название: 1–80 символов после обрезки пробелов; длительность: целое число 1–30.
- Начальная и конечная даты включаются в срок. Допускается выбрать прошлую или будущую дату старта.
- Часовой пояс берется из устройства при создании и сохраняется в челлендже.
- Только сервер определяет текущую дату. Отметить и отменить можно только сегодня и только внутри срока.
- Повторный PUT не дублирует отметку. Повторный DELETE не меняет результат.
- Процент = количество отметок / длительность × 100, округленный до целого.
- «Завершен» означает, что срок закончился; это не обязательно 100% выполнения.

## Подключение к Telegram

1. Создать бота через BotFather и получить токен. Сохранить токен только в серверном окружении; не в Git и не в клиентском коде.
2. Выбрать хостинг для постоянного Node.js-процесса и постоянного диска SQLite. Эта версия не рассчитана на несколько серверных экземпляров и эфемерный диск serverless-хостинга.
3. Выполнить `pnpm build`. Сервер автоматически раздает `dist/` вместе с API.
4. Настроить `NODE_ENV=production`, `DEV_AUTH=false`, `BOT_TOKEN`, `DATABASE_PATH`, `HOST` и `PORT`. Пример переменных — `.env.example`. Настоящий `.env` игнорируется Git.
5. Запустить `pnpm start` за HTTPS reverse proxy. В production запуск с DEV_AUTH завершается ошибкой.
6. В BotFather указать HTTPS URL приложения как Main Mini App или адрес кнопки меню.
7. Открыть из Telegram и проверить создание, отметку, перезапуск и изоляцию данных двух пользователей. Браузерный локальный профиль этого не доказывает.

Прямое открытие production-приложения в обычном браузере покажет просьбу открыть Telegram. Подписанные initData действуют один час; после истечения нужно переоткрыть приложение. Долгоживущая серверная сессия в MVP не реализована.

Архивирование, напоминания и групповые челленджи пока не реализованы. Архивирование оставлено для Дня 1. До публичного запуска для реальных пользователей нужно добавить удаление/экспорт персональных данных и согласовать срок хранения. Текущая версия предназначена для личного учебного тестирования.
