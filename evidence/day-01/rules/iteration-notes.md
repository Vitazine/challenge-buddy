# Почему изменены правила v1 → v2

Правила v1 были полноценными: реализация с ними прошла исходную приёмку. Ошибки намеренно не закладывались, результат после внешнего ревью не исправлялся. Изменён только набор инструкций для второго независимого запуска.

| Наблюдение первой генерации | Изменение v2 | Как оценивать влияние |
|---|---|---|
| Первый и второй check остановились на react-hooks/set-state-in-effect; исправление потребовало внутренних повторов | Явно описан асинхронный путь обновления состояния, запрещены обходы правила, добавлена ранняя проверка lint после изменения хука | Сравнить первые логи и отдельно число исправлений до финального результата; sandbox EPERM не считать ошибкой кода |
| Миграция v1 → v2 сохраняет данные, но дополнительный запуск на синтетической БД user_version=99 принят и создаёт таблицы | Прочитать версию до DDL; отклонять неподдерживаемую будущую версию без изменения схемы, закрывать соединение; проверить этот сценарий | Один и тот же future-schema-check.mjs на обеих генерациях. Этот диагностический критерий появился после v1 и учитывается отдельно от заранее определённой приёмки |
| Независимое ревью подтвердило корректное разделение календарного статуса и признака архива, идемпотентную дату, серверный запрет обеих операций с отметками | Удачные решения закреплены как явные соглашения проекта | Проверить, что второй запуск сохраняет их. Это стандартизация, а не доказанное исправление дефекта v1 |
| Защита от устаревших ответов рассмотрена статически; автоматические тесты не проверяют события и эффекты UI | Уточнены сценарии переключения списков, фонового ответа после мутации, возврата и последней страницы; требуется честно указывать способ проверки | Сравнить код и фактические отчёты. Отсутствие реальной проверки гонки остаётся ограничением, даже если код выглядит корректным |

## Что не менялось

Промпт, исходные продуктовые файлы, зависимости, общий файл предпочтений, модель и reasoning (наследуются без override), набор доступных инструментов и скиллов. Инструкции запуска отличаются только путём рабочей копии и номером каталога для снимка первой попытки. Вторая генерация не получала исходники или отчёт первой.

Внешние проверяющие агенты не исправляют генерации. Полные результаты, первые попытки и логи сохраняются отдельно. Новые UI-фреймворки, профили для Дня 2, стенд Дня 3, локальная модель и очередь автономных задач не создаются.
