## Принятый API-контракт

- `Challenge.archivedAt`: null или ISO UTC timestamp первого архивирования; status остаётся `upcoming | active | finished`. Архив даёт `canCheckIn=false`.
- `PUT /api/challenges/:id/archive`: без тела, 200 + Challenge; повтор сохраняет timestamp и данные. Владелец только из существующей авторизации, не из клиента. Неавторизованный запрос — 401; чужой/отсутствующий объект — одинаковый 404 NOT_FOUND; некорректный id или тело — 422.
- `GET /api/challenges?page=1&pageSize=20&archived=false`: по умолчанию обычный список; `archived=true` выбирает архив. Фильтр одинаков для items/total, owner-scoped, пагинация сохраняется. Только строковые true/false, неизвестные параметры отклоняются с 422.
- Детали архива доступны владельцу через прежний GET. PUT и DELETE `/check-ins/today` дают 409 CHALLENGE_ARCHIVED, история не меняется. Восстановления нет.
- SQLite v2: версия читается до DDL и journal_mode; новая БД и миграция известной v1 выполняются транзакционно; v2 не ALTER-ится повторно. Будущая версия отклоняется с закрытием соединения без изменения файла.
