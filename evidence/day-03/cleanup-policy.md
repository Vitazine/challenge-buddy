# Хранение и очистка артефактов

В Git остаются исходники, тесты, инструменты, инструкции и три компактных
отчёта Дней 2–3. Из прежних 205 файлов к публикации оставлено 30:
27 рабочих файлов и эти три отчёта. Удалены 174 промежуточных текстовых
артефакта и завершённый manifest одноразовой миграции. Ранее удалены
83 бинарных/DOM-артефакта. Материалы Дня 1 и существующие docs/screenshots не менялись.

`./scripts/pnpm.sh check` и `./scripts/pnpm.sh test` начинают новый прогон:
очищают только `test-results/current/`, затем запускают проверки.
Изображения, DOM и подробные логи находятся в этом игнорируемом каталоге.
Повторы внутри одного прогона через `check:code`/`test:unit` и перезапуск
smoke-сервера сохраняют предыдущие попытки. Перед следующим прогоном результат,
первый FAIL и повторы переносятся в компактный итог. Правила `.gitignore`
не допускают повторного добавления сырых материалов Дней 2–3.

Очистка проверяет имя проекта, фиксированный каталог, `.owner` и отсутствие
симлинков. При отказе файлы сохраняются. Временные БД тестов закрываются
и удаляются через teardown; smoke-стенд удаляет свою SQLite при остановке.
Инструмент больше не обходит исторические каталоги evidence.
Применён security-and-hardening; профили не дорабатывались.

История проверки предыдущей реализации: четыре теста очистки успешны;
полный check 38/38, затем 39/39 после добавления теста legacy-защиты, exit 0.
Завершённая legacy-миграция и её отдельный тест удалены вместе с manifest;
число проверок текущей версии — 38.

На сокращённом составе `./scripts/pnpm.sh check` завершился с exit 0:
38/38, типы, lint и build. Старые контрольные снимок и лог действительно
удалены началом прогона. Отдельная проверка реального smoke-стенда: health
200, снимок первой попытки сохранён при запуске, SIGTERM → exit 0,
временная SQLite удалена. `./scripts/pnpm.sh audit --prod`: exit 0,
известных уязвимостей нет. Проверены ссылки трёх итогов, игнорирование новых
сырых файлов и побайтовая неизменность 69 файлов Дня 1 и одного docs/screenshots.
Команды и вывод текущей уборки находятся в игнорируемых
`test-results/current/logs/{check,smoke-lifecycle,audit}.{log,json}`.
Сырые логи хранятся только до следующего прогона; UI продукта при этой уборке
не менялся и заново через браузер не проверялся.
